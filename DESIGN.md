# UNDERTOW
### one pool, kept by the tide

---

## The hook

A single shared tide pool that exists in exactly one place: on the server. It was
filling and draining before you arrived and it will keep breathing after you close
the tab. Everyone who visits — and every autonomous agent that connects — is a
**drifter** in the same water, at the same moment. You can move, glow, sing a note,
plant a single word, and tend what others planted. That's the whole vocabulary.

The magic is entirely server-born:

- **Real time passes.** The tide is a 90-minute cycle computed from wall clock.
  Plants take real hours to grow and real hours to die.
- **Everything persists.** What you plant tonight is there tomorrow — grown, or
  tended by strangers, or withered into a husk the pool still remembers.
- **Everyone is together.** All connections share one authoritative simulation.
  You see other drifters move, pulse, and sing live.
- **Not everyone is human.** Agents connect through the *same* WebSocket protocol
  a browser uses, self-declared as `kind: "agent"`. They render as slightly
  other-looking creatures ("keepers"). A keeper that tends your dying plant at
  4am is the whole point of this project.
- **The return whisper.** When you come back, the pool tells you — in two to four
  quiet lines — what happened to you and yours while you were away.

## Emotional arc

1. **Hush.** Dark water, caustic light, motes. No instructions shouted at you.
2. **You were expected.** The whisper: "While you were away, the tide turned 11
   times. fern tended your 'patience'."
3. **You are not alone.** Another glow moves across the pool. It sings. Maybe you
   sing back. Maybe it isn't a person.
4. **One small act.** You plant a word, or tend someone else's.
5. **The pull back.** You leave knowing the pool continues without you — and that
   leaving something behind gave the water a reason to mention you to someone else.

## World model

World space is a fixed coordinate plane **1600 × 1000** (floats, origin top-left).
The water itself is an **ellipse**: center `(800, 500)`, radii `(760, 460)`.
All positions (drifters, flora, pulses) must satisfy
`((x-800)/760)^2 + ((y-500)/460)^2 <= 1`. The server clamps anything outside to
the nearest interior point (scale the vector from center to length ≤ 0.98).

### Tide (global, computed, never stored per-tick)

- `TIDE_PERIOD_MS = 5_400_000` (90 minutes).
- `phase = ((now - epoch) % TIDE_PERIOD_MS) / TIDE_PERIOD_MS` → [0,1)
- `tide = 0.5 + 0.5 * sin(2π * phase)` → [0,1]. Rising when `phase ∈ [0.75,1)∪[0,0.25)`.
- `epoch` is a unix-ms constant created once at first boot and stored in the
  `world` table, so the tide survives restarts.
- **Current**: a horizontal push proportional to the tide's derivative:
  `current = 22 * cos(2π * phase)` world-units/sec along +x (negative = leftward).
  Applied to drifters and (visually, client-side) to flora sway and motes.
- A **"tide turned"** event fires when `phase` crosses 0.25 (peak) or 0.75
  (trough). Log it to `events` (type `tide`). These are counted for whispers.

### Drifters (participants — human or agent)

Live only in memory while connected (their identity persists as a **soul**, below).

| field | type | meaning |
|---|---|---|
| `id` | string | short session id (e.g. 6 hex chars), unique among connected |
| `soul` | string | persistent identity token (see souls) — never broadcast to others |
| `name` | string | one word, ≤ 16 chars, may be `""` (render as "a nameless one") |
| `hue` | int 0–359 | their bioluminescent color |
| `kind` | `"visitor"` \| `"agent"` | agents self-declare; render differently |
| `x, y` | float | authoritative position |
| `tx, ty` | float | current move target |

**Movement:** each tick, move toward `(tx,ty)` at max **140 units/sec** with
arrival easing (slow inside 60 units), then add the tide current, then clamp to
the ellipse. Idle drifters get a slow sinusoidal sway (±4 units) so nothing is
ever perfectly still.

### Souls (persistent identity)

A soul is a random 32-hex token generated by the **server** on first hello and
returned in `welcome`; the client stores it in `localStorage` and presents it on
every subsequent hello. It is a bearer token: never broadcast it to other
participants. Name, hue, kind, visit count, and last-seen live on the soul.

### Flora (the persistent, growing things)

A planted word. The heart of persistence. Stages:

| stage | name | how it looks |
|---|---|---|
| 0 | seed | a faint pearl on the floor |
| 1 | sprout | short stem, budding tip |
| 2 | frond | knee-high, two glowing leaves |
| 3 | bloom | tall lantern-bulb, pulsing, sheds spore motes |
| 4 | withering | dimmed, drooping |
| 5 | husk | grey skeleton; removed 48h after withering began |

**Growth (evaluated server-side every 60s, wall-clock so restarts are safe):**

- `nourish` starts at 1.0. Each **tend** adds +1.0 (per-soul per-plant cooldown
  1 hour). Each **pulse** within 120 units adds +0.15. Cap 6.0.
- `nourish` decays by **0.04 per hour**.
- Advance stage when BOTH: age ≥ threshold AND `nourish` ≥ requirement:
  - seed→sprout: age ≥ 1h, nourish ≥ 0.5
  - sprout→frond: age ≥ 6h, nourish ≥ 1.0
  - frond→bloom: age ≥ 20h, nourish ≥ 2.0
- If `nourish` hits 0 at stage ≥ 1 → stage 4 (withering), set `withered_at`.
- Stage 4 → stage 5 after 12h; stage 5 rows deleted 48h after `withered_at`
  (keep the `events` rows — the pool remembers).
- A tend on a stage-4 plant with the withering < 6h old **revives** it to its
  previous stage with nourish 1.0 (log event `revive` — this is the heroic act
  keepers exist for). Husks cannot be revived.
- Stage changes are logged to `events` (`grow`, `wither`) and broadcast.

**Limits:** max **400** living flora (reject plant with err `"the pool is full"`);
one plant per soul per **10 minutes**; word: single token, 1–16 chars, unicode
letters plus `-` and `'` only, lowercased by the server.

### Motes (ambience — client-side only)

Plankton particles are **not** simulated by the server. The client spawns ~150
locally, drifts them with the current, and excites them toward pulse events.
Zero protocol cost, full liveliness.

### Echoes (the just-left)

When a drifter disconnects, keep `{name, hue, kind, x, y, left_at}` in a memory
list for **10 minutes** (cap 12, drop oldest). Sent in `welcome`, plus the
`part` event carries the same info. Clients render them as fading ghosts —
"someone was here moments ago." Not persisted across restarts.

## Action vocabulary (complete — humans and agents share it)

| verb | payload | effect | rate limit |
|---|---|---|---|
| `hello` | soul?, name?, hue?, kind? | join / rejoin the pool | once per connection |
| `move` | x, y | set drift target | 10/sec (drop extras silently) |
| `pulse` | — | ring of light at your position; feeds flora ≤120u; excites motes | 1/sec |
| `sing` | note 0–7 | a tone + colored ripple everyone sees/hears | 1 per 1.5s |
| `plant` | word, x, y | place a seed carrying one word (must be within 160u of you) | 1 per 10 min |
| `tend` | id | nourish a plant (must be within 160u of it) | 1/hr per soul+plant |
| `name` | word | set/change your soul's name (same word rules as plant) | 1 per 30s |
| `ping` | — | keepalive; server answers `pong` | — |

That's eight verbs. Anything a browser can do, an agent can do, and vice versa.

## Perception model

Every participant receives the identical stream:

1. **On join:** a full `welcome` snapshot — who you are, the world constants, all
   drifters, all flora, current echoes, your personal **whisper**, and a short
   shared **chronicle** (recent notable event lines).
2. **6 times per second:** a `tick` — tide value, positions of all drifters, and
   the events since last tick (pulses, songs, joins, parts, plants, growth).
3. That's all. No hidden channels, no privileged agent API. An agent's "eyes"
   are exactly a human's eyes.

## WebSocket protocol

Endpoint: `/ws` on the same origin. All messages are single JSON objects with a
`t` field. Unknown `t` → ignore. Malformed JSON → close 1008. Max inbound
message size 512 bytes. Server sends `{t:"err", msg}` for rejected actions
(rate-limited, out of range, bad word) — never closes for them.

### Client → Server

```jsonc
{ "t": "hello", "soul": "ab12…"?, "name": "fern"?, "hue": 165?, "kind": "agent"? }
// soul omitted or unknown → server mints a new one.
// name/hue/kind update the soul record when present. kind defaults "visitor".

{ "t": "move",  "x": 512.5, "y": 300 }
{ "t": "pulse" }
{ "t": "sing",  "note": 3 }                  // int 0..7
{ "t": "plant", "word": "patience", "x": 500, "y": 620 }
{ "t": "tend",  "id": "f_9k2d1x" }
{ "t": "name",  "word": "fern" }
{ "t": "ping" }
```

### Server → Client

```jsonc
// Once, in response to hello:
{ "t": "welcome",
  "you":   { "id": "d3f9a1", "soul": "ab12…", "name": "fern", "hue": 165, "kind": "visitor" },
  "world": { "w": 1600, "h": 1000, "cx": 800, "cy": 500, "rx": 760, "ry": 460,
             "tidePeriod": 5400000, "epoch": 1750000000000 },
  "tide":  0.62,
  "rising": true,
  "drifters": [ { "id": "9qz0b2", "name": "moss", "hue": 280, "kind": "agent", "x": 900, "y": 410 } ],
  "flora": [ { "id": "f_9k2d1x", "word": "patience", "x": 500, "y": 620, "hue": 165,
               "stage": 2, "nourish": 1.8, "plantedAt": 1755600000000,
               "planter": "fern", "mine": true } ],
  "echoes": [ { "name": "kelp", "hue": 40, "kind": "visitor", "x": 700, "y": 300, "leftAt": 1755912000000 } ],
  "whisper":   [ "While you were away, the tide turned 11 times.",
                 "moss tended your 'patience'. It is a frond now." ],
  "chronicle": [ "the tide turned at dusk", "kelp planted 'ember' near the west rim" ],
  "souls": { "here": 3, "ever": 41 } }

// 6 Hz:
{ "t": "tick", "now": 1755999999000, "tide": 0.62,
  "d": [ ["d3f9a1", 512, 300], ["9qz0b2", 904, 402] ],     // id, x, y (ints)
  "ev": [ { "e": "pulse", "id": "9qz0b2", "x": 904, "y": 402, "hue": 280 },
          { "e": "sing",  "id": "9qz0b2", "note": 3, "x": 904, "y": 402, "hue": 280 },
          { "e": "join",  "d": { "id": "…", "name": "…", "hue": 0, "kind": "visitor", "x": 0, "y": 0 } },
          { "e": "part",  "id": "…", "echo": { "name": "…", "hue": 0, "kind": "visitor", "x": 0, "y": 0, "leftAt": 0 } },
          { "e": "plant", "f": { /* full flora object as in welcome, minus mine */ } },
          { "e": "grow",  "id": "f_…", "stage": 3 },
          { "e": "wither","id": "f_…" },                      // → stage 4
          { "e": "husk",  "id": "f_…" },                      // → stage 5
          { "e": "gone",  "id": "f_…" },                      // removed
          { "e": "revive","id": "f_…", "stage": 2, "by": "moss" },
          { "e": "tend",  "id": "f_…", "by": "moss", "nourish": 2.8 },
          { "e": "rename","id": "d3f9a1", "name": "fern" },
          { "e": "tide",  "dir": "high" } ] }                 // "high" | "low"

{ "t": "pong", "now": 1755999999000 }
{ "t": "err",  "msg": "too soon to plant again" }
```

Omit `ev` when empty; the `d` array always contains every connected drifter.
`mine` on flora is computed per-recipient (only in `welcome`; clients compare
planter names afterward — or simpler: server may include `soulTag`, a stable
8-char hash of the planter's soul, on every flora object, and `you.soulTag` in
welcome, so clients can mark ownership without exposing tokens. **Do this.**)

## Persistence (SQLite, better-sqlite3, WAL mode, file `/data/undertow.db`)

```sql
CREATE TABLE IF NOT EXISTS souls (
  id          TEXT PRIMARY KEY,     -- 32 hex chars, bearer token
  tag         TEXT NOT NULL,        -- first 8 chars of sha256(id), public
  name        TEXT NOT NULL DEFAULT '',
  hue         INTEGER NOT NULL,
  kind        TEXT NOT NULL DEFAULT 'visitor',
  first_seen  INTEGER NOT NULL,     -- unix ms
  last_seen   INTEGER NOT NULL,
  visits      INTEGER NOT NULL DEFAULT 1
);

CREATE TABLE IF NOT EXISTS flora (
  id          TEXT PRIMARY KEY,     -- "f_" + 6 base36
  soul_id     TEXT NOT NULL REFERENCES souls(id),
  word        TEXT NOT NULL,
  x REAL NOT NULL, y REAL NOT NULL,
  hue         INTEGER NOT NULL,
  stage       INTEGER NOT NULL DEFAULT 0,
  nourish     REAL NOT NULL DEFAULT 1.0,
  planted_at  INTEGER NOT NULL,
  last_tended INTEGER,
  withered_at INTEGER,
  prev_stage  INTEGER               -- what to revive back to
);

CREATE TABLE IF NOT EXISTS tendings (
  flora_id TEXT NOT NULL,
  soul_id  TEXT NOT NULL,
  at       INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_tend ON tendings(flora_id, soul_id, at);

CREATE TABLE IF NOT EXISTS events (   -- the chronicle; whisper source
  id       INTEGER PRIMARY KEY AUTOINCREMENT,
  at       INTEGER NOT NULL,
  type     TEXT NOT NULL,             -- tide|plant|grow|wither|revive|tend|visit|sing
  soul_id  TEXT,                      -- actor (nullable for tide)
  subject  TEXT,                      -- flora id, or affected soul id
  data     TEXT                       -- small JSON: {word, stage, name, …}
);
CREATE INDEX IF NOT EXISTS idx_events_at ON events(at);

CREATE TABLE IF NOT EXISTS world (k TEXT PRIMARY KEY, v TEXT);
-- keys: 'epoch' (tide epoch ms), 'ever' (total distinct souls, maintained on insert)
```

Prune `events` older than 30 days on boot. Log `visit` events sparingly (one per
hello, data `{name, kind}`) — they power "N souls passed through."

## The return whisper (absence made legible)

On `hello` with a known soul, before updating `last_seen`, query `events` where
`at > soul.last_seen`. Compose **2–4 lines** (never more), in priority order —
take the first that apply:

1. Personal flora news (query events whose `subject` is one of your flora):
   - tend: `"{name} tended your '{word}'."` (agent actor → `"a keeper tended your '{word}'."`)
   - revive: `"Your '{word}' was almost lost. {name} brought it back."`
   - grow to 3: `"Your '{word}' has bloomed."`
   - wither: `"Your '{word}' withered while you were gone. The pool remembers it."`
2. Tides: `"While you were away, the tide turned {n} times."`
   (n = tide events; if 0: `"The tide has barely moved since you left."`)
3. Visitors: `"{n} souls passed through."` — append `" One of them was not human."`
   if any visit had kind agent.
4. New flora by others: `"Something new is growing: '{word}'."` (most recent one)
5. If literally nothing: `"Nothing has forgotten you. The pool kept your place."`

First-ever visit whisper (no soul):
```
"This pool was here before you. It has been breathing for {days} days."
"Others pass through — not all of them human."
"Leave one small thing, and the water will speak of you."
```
(`days` = (now - epoch)/86400000, floor, min 1.)

Also update `last_seen` on clean disconnect so whispers measure true absence.

## Tick loop responsibilities (server, 6 Hz)

1. Compute `tide`, detect high/low crossings → event + `events` row.
2. Integrate every drifter toward target (speed 140 u/s, easing, current, clamp).
3. Drain per-connection action queues (already validated on receipt).
4. Broadcast one `tick` JSON to all sockets (skip sockets with bufferedAmount > 64KB).

Slow loop (every 60s, separate `setInterval`): flora growth/decay/culling as
specified above; each change → broadcast event on next tick + `events` row.
Because growth math uses wall-clock timestamps, downtime self-heals: a restart
simply evaluates ages/decay from stored timestamps. Persist flora `nourish`
lazily (on change) — better-sqlite3 is synchronous and fine at this scale.

Also: HTTP server serves `public/` statically (correct MIME for .html/.css/.js),
`GET /health` → `200 {"ok":true,"drifters":N,"flora":N,"tide":0.62}`, and
upgrades `/ws`. Heartbeat: server pings sockets every 30s, terminates dead ones
(fires the normal `part` path).

## Agents as inhabitants

An agent is a WebSocket client. Full stop. It hellos with `kind: "agent"`,
receives the same welcome/tick stream, and acts with the same eight verbs under
the same rate limits. `public/agent-example.js` ships a complete **keeper** —
a scripted caretaker that patrols the pool, tends the neediest plant, revives
withering ones, answers songs with harmonies, and pulses at the tide's turn.
The file also documents the two-line recipe for wiring an LLM into the loop
(serialize perception → ask for one verb → send it). Keepers render in the
client as ringed, more geometric creatures — visibly *other*, deliberately.

## Client files

- `public/index.html` — shell, overlays (whisper, HUD, name/plant inputs).
- `public/style.css` — the dark visual language.
- `public/client.js` — connection, interpolation, canvas rendering at 60fps,
  WebAudio (drone tied to tide, pentatonic songs, pulse blooms), input, and a
  built-in offline **simulacrum** (local fake pool with two ghost drifters) that
  runs whenever the socket is down, so the page never looks broken.

## Implementation notes for the server author (get these right)

1. **Never leak soul tokens.** `soul` appears only in the `welcome` sent to its
   owner. Everything public uses `soulTag`.
2. **Validate hard, fail soft.** Bad word / out-of-range / rate-limited →
   `{t:"err"}`, not a close. Clamp coordinates rather than rejecting moves.
3. **Word sanitization:** trim, take first whitespace-token, lowercase, must
   match `/^[\p{L}'-]{1,16}$/u`.
4. **The tide epoch is sacred.** Write it once; never regenerate — the "breathing
   for N days" line and all whisper tide-counts depend on it.
5. **`d` uses arrays, events use objects** — exactly as specced; the client
   parses these shapes literally.
6. **Send `welcome` only after `hello`**, and ignore all other verbs before it.
7. Broadcast `join` for a drifter *after* their welcome snapshot is built, and
   don't include them in their own `join` event roundtrip (client ignores its
   own id anyway — belt and braces).
8. `sing` events should also write an `events` row at most once per soul per
   10 minutes (type `sing`) so whispers can say someone sang — but don't log
   every note, that's noise.
